# 災害時の信頼性評価付きマップ型情報共有Webアプリ 要件定義書

- チーム名：さくちゃんず
- 開発目的：災害時のデマ情報の拡散防止と、信頼性を判断しやすい情報共有の実現
- 開発形式：Webアプリケーション
- 開発対象：授業用プロトタイプ
- ステータス：要件定義 初版

---

# 1. プロジェクト概要

## 1.1 背景

災害発生時には、SNSなどを通じて大量の情報が発信される。

しかし、投稿された情報の真偽を判断することは難しく、誤った情報が拡散されることで、避難行動の混乱や救助活動への悪影響が発生する可能性がある。

また、SNSでは情報が時系列で流れていくため、特定の場所で何が起きているのか、現在の状況がどうなっているのかを把握しにくい。

本プロジェクトでは、災害情報を地図上に集約するとともに、投稿場所の位置情報やAIによる画像解析結果を提示することで、利用者が情報の信頼性を判断しやすい環境を実現する。

## 1.2 目的

本システムは、以下の実現を目的とする。

1. 災害情報を地図上に集約する。
2. 被災者が現地の状況を写真付きで共有できるようにする。
3. GPS情報を利用し、投稿場所との位置的な整合性を確認する。
4. AIを利用して、投稿写真と周辺画像の整合性を評価する。
5. 投稿写真とストリートビューなどを比較し、利用者自身が信頼性を判断できるようにする。
6. 同一地点の災害情報を時系列で確認できるようにする。
7. 最新情報と整合性の高い情報を優先的に表示する。

## 1.3 基本方針

本システムでは、AIが投稿の真偽を断定するのではなく、複数の判断材料を利用者に提供する。

信頼性の判断材料は以下の3つとする。

1. GPSによる位置情報の整合性
2. AIによる画像の整合性評価
3. 投稿写真・ストリートビュー・過去投稿写真による利用者自身の確認

GPSとAIの評価結果は別々に表示し、最終的な判断は利用者自身が行う。

# 2. 対象ユーザー

## 2.1 対象

一般の被災者を対象とする。

## 2.2 利用方法

- ユーザー登録・ログインは不要とする。
- 誰でも災害情報を閲覧できる。
- 誰でも写真付きの災害情報を投稿できる。
- 位置情報の取得には利用者の許可を必要とする。
- 投稿者は専用リンクから自分の投稿を編集・削除できる。

# 3. 機能要件

## 3.1 地図表示機能

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | 地図表示 | Webアプリ上に地図を表示する |
| F-02 | 現在地表示 | 利用者の現在地を表示する |
| F-03 | 投稿ピン表示 | 災害情報を地図上のピンで表示する |
| F-04 | 投稿詳細表示 | ピンを選択すると詳細情報を表示する |
| F-05 | 投稿優先表示 | 最新3件と信頼性の高い3件を優先表示する |

### 投稿の優先表示

同一地点に複数の投稿が存在する場合、以下の情報を優先表示する。

- 最新の投稿3件
- GPS・AIなどの検証結果から整合性が高いと評価された投稿3件

同じ投稿が両方に含まれる場合は、重複表示しない。

それ以外の投稿もデータベースに保存し、過去の投稿履歴から確認できるようにする。

※信頼性の高い投稿を選択する具体的な評価基準は詳細設計で決定する。

---

## 3.2 災害情報投稿機能

| ID | 機能 | 内容 |
|---|---|---|
| F-06 | 写真投稿 | カメラ撮影・既存写真のアップロードに対応する |
| F-07 | 説明文入力 | 災害状況を自由記述する |
| F-08 | 投稿場所指定 | GPSまたは地図上で場所を指定する |
| F-09 | 投稿日時記録 | サーバー側で投稿時刻を保存する |
| F-10 | 投稿公開 | 投稿直後に地図へ反映する |
| F-11 | 投稿編集 | 専用リンクから投稿を編集する |
| F-12 | 投稿削除 | 専用リンクから投稿を削除する |

### 投稿内容

投稿時に入力・取得する情報は以下とする。

- 投稿写真
- 災害状況の説明文
- 投稿場所（緯度・経度）
- 投稿日時
- 写真のメタデータ（取得可能な場合）
- 投稿時のGPS位置情報

災害の種類による分類機能は設けない。

### 投稿公開

投稿は送信後、直ちに地図上に表示する。

AI検証が完了していない場合は「未検証」と表示し、検証完了後に結果を反映する。

## 3.3 GPS検証機能

| ID | 機能 | 内容 |
|---|---|---|
| F-13 | GPS取得 | 投稿開始時に位置情報の取得を開始する |
| F-14 | 時系列記録 | 最大30秒間、複数の位置情報を記録する |
| F-15 | 距離計算 | 投稿場所と取得位置の距離を算出する |
| F-16 | 位置整合性評価 | 投稿場所から極端に離れた位置での投稿を検出する |
| F-17 | GPS検証結果表示 | 投稿詳細画面に結果を表示する |

### GPS取得方法

1. 利用者が投稿画面を開く。
2. 位置情報の取得許可を求める。
3. 許可された場合、位置情報の取得を開始する。
4. 最大30秒間、複数回の位置情報を取得する。
5. 緯度・経度・取得時刻・取得精度を記録する。
6. 投稿完了時に位置情報と投稿場所を比較する。

### GPSの評価方法

| 判定 | 内容 |
|---|---|
| 位置情報に大きな矛盾なし | 投稿場所とGPS位置が近い |
| 位置情報に注意が必要 | 投稿場所とGPS位置が極端に離れている |
| 判定不可 | GPS情報が取得できない |

距離の判定基準は実機テスト後に決定する。

GPSの取得位置は、写真の撮影場所や投稿内容の真偽を証明するものではない。

また、GPSの生データや移動履歴は一般利用者に公開しない。

---

## 3.4 AI画像検証機能

| ID | 機能 | 内容 |
|---|---|---|
| F-18 | AI画像解析 | 投稿写真をAIで解析する |
| F-19 | 周辺画像比較 | 投稿写真と周辺画像の特徴を比較する |
| F-20 | 過去投稿比較 | 同一地点の過去投稿写真と比較する |
| F-21 | AI結果表示 | 画像の整合性に関する結果を表示する |
| F-22 | 検証状態表示 | 検証中・完了・判定不可などを表示する |

### AI検証の流れ

1. 利用者が写真を投稿する。
2. 投稿場所の位置情報を取得する。
3. 比較対象となる画像を取得する。
4. 投稿写真と比較対象画像をAIに入力する。
5. 建物・道路・標識などの特徴を比較する。
6. 画像の整合性を評価する。
7. 評価結果と理由を保存する。
8. 投稿詳細画面に結果を表示する。

### 比較対象

以下の2種類を使用する。

1. Googleストリートビューの画像
2. 同一地点に投稿された過去の写真

### AIの評価結果

| 判定 | 内容 |
|---|---|
| 一致の可能性が高い | 共通する特徴が複数確認できる |
| 判断困難 | 比較材料が不足している |
| 不一致の可能性が高い | 明確な相違点が確認できる |

AIの判定結果は参考情報として扱い、投稿内容の真偽を断定しない。

### 技術的制約

Googleストリートビュー画像を外部AIで解析する方法については、Google Maps Platformの利用条件を確認したうえで実装方法を確定する。

---

## 3.5 写真のメタデータ検証

| ID | 機能 | 内容 |
|---|---|---|
| F-23 | EXIF取得 | 写真に含まれるメタデータを取得する |
| F-24 | 日時整合性確認 | 撮影日時と投稿日時を比較する |
| F-25 | 編集痕跡確認 | メタデータに編集ソフト等の情報があるか確認する |
| F-26 | 検証結果表示 | 検出された情報を利用者に表示する |

### 確認する情報

- 撮影日時
- 写真に記録された位置情報
- カメラ情報
- 編集ソフトの情報
- その他取得可能なメタデータ

### 判定方針

以下のような場合、注意情報を表示する。

- 撮影日時が投稿日時より未来になっている。
- 撮影場所と投稿場所が大きく異なる。
- 画像編集ソフトの使用を示すメタデータが存在する。

ただし、画像編集ソフトの使用が確認された場合でも、悪意ある改ざんとは断定しない。

また、編集履歴が存在しない場合でも、改ざんされていないことを保証するものではない。

メタデータが取得できない場合は「確認できない」と表示する。

## 3.6 時系列表示機能

| ID | 機能 | 内容 |
|---|---|---|
| F-27 | 投稿履歴保存 | 同一地点の過去投稿を保存する |
| F-28 | 時系列表示 | 投稿を日時順に表示する |
| F-29 | 写真比較 | 現在と過去の投稿写真を比較できるようにする |
| F-30 | GPS履歴保存 | 投稿時に取得した位置データを時系列で保存する |

### 時系列データの種類

本システムでは、2種類の時系列データを扱う。

#### ① GPSの時系列位置データ

投稿開始時から最大30秒間、位置情報を複数回取得する。

保存する情報：

- 取得時刻
- 緯度
- 経度
- 位置情報の精度

主な用途：

投稿場所と投稿時の位置情報の整合性を確認する。

#### ② 災害投稿の時系列データ

同一地点に投稿された災害情報を時系列で保存する。

保存する情報：

- 投稿日時
- 投稿場所
- 投稿写真
- 説明文
- 検証結果

主な用途：

災害状況の時間的な変化を確認する。

# 11. 開発上の注意事項

1. AIの判定結果は参考情報であり、投稿の真偽を保証しない。
2. GPSの取得位置は、写真の撮影場所を証明するものではない。
3. メタデータの編集痕跡は、悪意ある改ざんの証明にはならない。
4. ストリートビュー画像は、必ずしも現在の状況を示していない。
5. 古い災害情報を現在の情報と誤認しないよう、投稿日時を明示する。
6. 利用者のGPS履歴は一般公開しない。
7. プロトタイプとして実装可能な範囲を優先し、複雑な機能は段階的に追加する。
